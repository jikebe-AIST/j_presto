>j_presto
j_prestoパッケージには、分子動力学（MD）シミュレーション、
トラジェクトリ処理、構造解析、および分子設計のためのプログラムが含まれます。

使用法:
    j_presto SUBPROGRAM [arguments]

詳細を確認するには、以下のサブプログラム名を入力してください。

シミュレーション系の準備と実行:
    initpep         folding simulation用の伸長ペプチド構造を作成
    pdb_alignfit    配列アラインメントに基づいてquery構造をreferenceへ重ね合わせ
    nt_gen          PREPファイルとPDBファイルから原子名対応表を作成
    nt_conv         対応表に基づいて残基名・原子名を変換
    gen_db          AMBERパラメータからトポロジーデータベース（*.tpldb）を作成
    prep            PDB、トポロジー（*.tpl）、SHAKE（*.shk）入力を作成
    pepchk          PDB構造中のペプチド結合ω角を検査
    md_run          MDシミュレーションまたはエネルギー最小化を実行
    batch_set       複数MD run用のファイルとディレクトリを準備
    GEprep          一般化アンサンブル計算用パラメータファイル（*.nf）を作成

トラジェクトリ処理と解析:
    traj_conv       j_prestoのCOD/CODSと外部トラジェクトリ形式を相互変換
    Ens_Ana         構造アンサンブルとトラジェクトリを解析
    DISTIL          二つの構造アンサンブル間の差を検出・解釈
    PCAaxis         主成分軸を計算
    PCAproj         構造をPCA部分空間へ射影
    distrib         分布、統計量、自由エネルギー地形を計算
    pick_conf       反応座標の条件に基づいて構造を抽出・順位付け
    ttp_se          TTPの独立run間で重み付き平均と標準誤差を計算
    pdb_movie       連続したPDB構造をmulti-model PDBトラジェクトリへ結合

分子設計と可視化:
    MSPER           酵素の位置選択性を改善する変異部位を予測
    conmut          コンセンサス配列解析から安定化変異を提案
    struct_formula  SMILESから二次元分子構造式を描画し、必要に応じてPDB原子名を表示

ユーティリティと文書:
    get_tmpl        入力ファイルと実行スクリプトのtemplateをコピー
    genlist         トラジェクトリファイルリストと解析範囲を作成
    manual          この対話型マニュアルを開く

並列実行ランチャー:
    j_presto_mpi     複数のOpenMP MD runをembarrassingly parallelなMPI jobとして実行
    j_presto_master  複数のOpenMP MD runをmaster-worker方式のMPI jobとして実行

MDエンジンはOpenMP並列化に対応しています。GPUは直接使用せず、一つの
md_runプロセス自体はMPI並列化されません。多数の独立OpenMP runをまとめて
実行する場合は、上記の並列実行ランチャーを使用してください。
>initpep
@u:j_presto,n:pdb_alignfit
"j_presto initpep"は、folding simulationの初期構造として使用する
伸長ペプチド構造を作成します。通常のMDではPDBの実験構造やAlphaFold等の
モデル構造を初期構造にしますが、folding simulationでは、完全にほどけた
構造からnative構造へfoldする過程を調べるため、伸長構造が必要です。

使用法: j_presto initpep INPUT [options]

INPUTには、次のいずれかでアミノ酸配列を指定します。
    1 : 一文字表記のアミノ酸配列文字列
    2 : FASTAファイル
    3 : PDBファイル
PDBを入力した場合、座標は使用せず配列のみを読み取ります。PDBにSSBOND recordが
含まれる場合、その情報は出力PDBへ引き継がれます。

オプション:
    initpep -o    出力PDBファイル
    initpep -H    helixとして作成する領域
    initpep -s    S-S結合を形成するCYSの組

詳細は、例えば "initpep -o" を入力してください。
>initpep -o
@u:initpep,n:initpep -H
使用法: j_presto initpep -o OUTPUT

出力PDBファイル名を指定します。既定値は "output.pdb" です。
>initpep -H
@u:initpep,p:initpep -o,n:initpep -s
使用法: j_presto initpep -H FIRST_RESIDUE:LAST_RESIDUE[,FIRST_RESIDUE2:LAST_RESIDUE2[,...]]

initpepは通常、入力配列からφ = 180°、ψ = 180°の伸長構造を作成します。
指定した領域をhelix構造にする場合、このオプションを使用します。
例えば、残基1–10と20–30をhelixにする場合は次のように指定します。
    j_presto initpep -H 1:10,20:30
>initpep -s
@u:initpep,p:initpep -H
使用法: j_presto initpep -s CYS1:CYS2[,CYS3:CYS4[,...]]

S-S結合を形成するCYS残基の組を指定します。指定内容は出力PDBのSSBOND recordに
書き込まれます。入力PDBにSSBOND recordがある場合は自動的に継承されるため、
再指定は不要です。一文字配列、FASTA、またはSSBOND情報のないPDBを入力する場合に
使用します。

この指定はSSBOND情報を追加するだけであり、出力座標は伸長構造（-H使用時は一部
helix）のままです。指定したCYS間距離は自動的には短くなりません。CYS同士を
近づけるには、出力PDBに対して "j_presto md_run" によるエネルギー最小化を
行ってください。複数のS-S結合を同時に形成させる場合、距離拘束が競合して、
すべての結合距離を満たす構造へ収束しないことがあります。
>pdb_alignfit
@u:j_presto,p:initpep,n:nt_gen
"j_presto pdb_alignfit"は、二つのPDBファイルのアミノ酸配列を
アラインメントし、その対応関係に基づいて構造を重ね合わせます。reference構造と
query構造の配列一致率を計算し、query構造をreferenceへ重ね合わせた新しいPDBを
出力します。

Ens_Anaでも構造重ね合わせは可能ですが、pdb_alignfitは特に配列相同性の低い
二つのタンパク質構造の比較用に設計されています。例えば、目的タンパク質Aの
単体構造と、相同タンパク質Bのligand複合体構造がある場合、Aをreference、Bを
queryとして重ね合わせることで、BのligandをA上へ配置した複合体モデルを作れます。

本プログラムはインターネット接続を必要とせず、すべての処理をローカルで行います。
配列データを外部へ送信しないため、機密情報を含む構造にも利用できます。

使用法: j_presto pdb_alignfit REFERENCE_PDB_FILE QUERY_PDB_FILE [options]

必須引数:
    REFERENCE_PDB_FILE    重ね合わせの基準とするPDB
    QUERY_PDB_FILE        referenceへ重ね合わせるPDB

オプション:
    pdb_alignfit -a      alignment mode
    pdb_alignfit -s      重ね合わせに使用する原子（caまたはbackbone）
    pdb_alignfit -ogs    gap opening score
    pdb_alignfit -egs    gap extension score
    pdb_alignfit -sm     substitution matrix
    pdb_alignfit -o      出力PDBファイル名

詳細は、例えば "pdb_alignfit -a" を入力してください。
>pdb_alignfit -a
@u:pdb_alignfit,n:pdb_alignfit -s
使用法: j_presto pdb_alignfit -a {global, local}

alignment modeをglobalまたはlocalに設定します。global alignmentは配列全体を
対応付け、local alignmentは最もよく一致する部分配列を探索します。既定値はlocalです。
長い配列ではglobal alignmentの計算量が大きくなることがあります。
>pdb_alignfit -s
@u:pdb_alignfit,p:pdb_alignfit -a,n:pdb_alignfit -ogs
使用法: j_presto pdb_alignfit -s {ca, backbone}

構造重ね合わせに使用する原子を指定します。"ca"はCα原子、"backbone"は
主鎖原子（CA、C、N、O）を使用します。既定値は"ca"です。
>pdb_alignfit -ogs
@u:pdb_alignfit,p:pdb_alignfit -s,n:pdb_alignfit -egs
使用法: j_presto pdb_alignfit -ogs OPEN_GAP_SCORE

配列alignmentでgapを新たに導入する際のpenaltyを指定します。既定値は-10です。
>pdb_alignfit -egs
@u:pdb_alignfit,p:pdb_alignfit -ogs,n:pdb_alignfit -sm
使用法: j_presto pdb_alignfit -egs EXTEND_GAP_SCORE

配列alignmentで既存gapを延長する際のpenaltyを指定します。既定値は-0.2です。
>pdb_alignfit -sm
@u:pdb_alignfit,p:pdb_alignfit -egs,n:pdb_alignfit -o
使用法: j_presto pdb_alignfit -sm MATRIX_NAME

配列alignmentに使用するsubstitution matrixを指定します。異なるアミノ酸を
対応付ける際のscoreを定義します。既定値は"BLOSUM62"です。
>pdb_alignfit -o
@u:pdb_alignfit,p:pdb_alignfit -sm
使用法: j_presto pdb_alignfit -o OUTPUT_PDB_FILE_NAME

reference構造へ重ね合わせたquery構造を保存するPDBファイル名を指定します。
既定値は"superimposed_structure.pdb"です。
>nt_gen
@u:j_presto,p:pdb_alignfit,n:nt_conv
"j_presto nt_gen"は、PREP残基定義とPDB構造の間で原子名の対応表を
作成します。

標準アミノ酸や核酸残基のパラメータは通常force field databaseに含まれますが、
非標準残基や低分子ligandでは、外部parameterization workflowで独自PREPファイルを
作る場合があります。その際、PREP内の原子名が元のPDBと異なることがあります。

nt_genは分子の結合関係から原子対応を推定します。原子間距離から暫定的なPDB結合
グラフを作り、PREPに記述されたtopologyと比較します。出力された表は
"j_presto nt_conv"へ渡し、原子名と残基名を一貫して変換できます。

使用法:
    j_presto nt_gen INPUT.prep INPUT.pdb [options]

必須入力:
    INPUT.prep    PREP残基定義ファイル
    INPUT.pdb     対応する分子を含むPDB構造

オプション:
    nt_gen -o    出力対応表。既定値: table.nt
    nt_gen -t    PDBの暫定結合判定距離。既定値: 1.8 Å

詳細は "nt_gen -o" または "nt_gen -t" を入力してください。
>nt_gen -o
@u:nt_gen,n:nt_gen -t
使用法: j_presto nt_gen -o OUTPUT_FILE_NAME

出力する原子名対応表を指定します。既定値は"table.nt"です。
>nt_gen -t
@u:nt_gen,p:nt_gen -o
使用法: j_presto nt_gen -t THRESHOLD_DISTANCE

PDB中の二原子間に共有結合があると判定する距離閾値を指定します。既定値は1.8 Åです。
原子間距離がこの値未満の場合に結合ありと判定し、その結合情報とPREPの結合情報を
比較して原子名の対応を推定します。
>nt_conv
@u:j_presto,p:nt_gen,n:gen_db
標準20アミノ酸や核酸塩基のparameterは通常あらかじめ用意されていますが、
特殊アミノ酸や低分子ligandでは独自PREPファイルが必要になります。外部プログラムで
parameterを作成すると、元のPDBとPREPで原子名が変わり、手作業で対応付けるのは
煩雑です。"j_presto nt_gen"で対応表を作成し、"j_presto nt_conv"でその表に
基づいて名前を変換できます。

nt_convは、指定したname tableに従ってPDBまたはPREP内の残基名・原子名を変換します。
name tableでは左側が元の名前、右側が変換後の名前です。逆変換も可能です。

使用法: j_presto nt_conv INPUT_TABLE_NAME INPUT_FILE_NAME [options]

必須引数:
    INPUT_TABLE_NAME    元名と新名の対応を記したname table
    INPUT_FILE_NAME     変換対象のPDBまたはPREP

オプション:
    nt_conv -o      出力ファイル名
    nt_conv -r      逆方向に変換
    nt_conv -rh     変換対象残基のHを削除。allでPDB中の全Hを削除
    nt_conv -ra     出力PDBのatom IDを連番へ変更
    nt_conv -rr     出力PDBのresidue IDを連番へ変更
    nt_conv -rph    PREP中のH原子名を結合相手に基づいて変更

詳細は、例えば "nt_conv -o" を入力してください。
>nt_conv -o
@u:nt_conv,n:nt_conv -r
使用法: j_presto nt_conv -o OUTPUT

出力するPDBまたはPREPのファイル名を指定します。未指定時は"output.pdb"または
"output.prep"です。
>nt_conv -r
@u:nt_conv,p:nt_conv -o,n:nt_conv -rh
使用法: j_presto nt_conv -r

変換方向を反転します。通常はname table左側の元名から右側の新名へ変換しますが、
このオプションを指定すると新名から元名へ戻します。
>nt_conv -rh
@u:nt_conv,p:nt_conv -r,n:nt_conv -ra
使用法: j_presto nt_conv -rh    または    j_presto nt_conv -rh all

PDB中で名前を変換した残基に属するH原子を削除します。"all"を付けると、PDB中の
すべてのH原子を削除します。
>nt_conv -ra
@u:nt_conv,p:nt_conv -rh,n:nt_conv -rr
使用法: j_presto nt_conv -ra

出力PDBのatom IDを1からの連番に付け直します。
>nt_conv -rr
@u:nt_conv,p:nt_conv -ra,n:nt_conv -rph
使用法: j_presto nt_conv -rr

出力PDBのresidue IDを1からの連番に付け直します。
>nt_conv -rph
@u:nt_conv,p:nt_conv -rr
使用法: j_presto nt_conv -rph

変換後PREP内のH原子名を、結合相手の原子に基づいて適切な形式へ変更します。
PDBとPREPではH原子の命名規則が異なる場合があるため、シミュレーション入力として
一貫した命名が必要なときに使用します。
>gen_db
@u:j_presto,p:nt_conv,n:prep
"j_presto gen_db"は、j_presto用topology database（*.tpldb）と
溶媒座標ファイル（*.slv）を作成します。AMBER形式のparameter fileを
"j_presto gen_db -i"で指定します。

オプション:
    gen_db -i     入力AMBER parameter file
    gen_db -o     出力ファイル名
    gen_db -rr    残基名の変更
    gen_db -s     出力する溶媒座標ファイル（*.slv）

詳細は、例えば "gen_db -i" を入力してください。
"j_presto get_tmpl gen_db"を実行すると、gen_db実行scriptのtemplateを取得できます。
>gen_db -i
@u:gen_db,n:gen_db -o
使用法:
    j_presto gen_db -i INPUT [INPUT ...]

一つ以上のAMBER parameter fileを指定します。dat、in、prep、lib、frcmod、leaprc形式に
対応します。同じparameterが複数回定義された場合、後から読み込んだ定義を優先します。

環境変数J_PRESTO_AMBER_DATABASE_PATHにAmberTools parameter databaseのdirectoryを
設定すると、その配下のファイルをfull pathなしで指定できます。

AmberToolsはAMBER projectから別途配布されています。利用時は同projectのdocumentと
licenseに従ってください。
>gen_db -o
@u:gen_db,p:gen_db -i,n:gen_db -rr
使用法: j_presto gen_db -o OUTPUT

出力ファイルのbasenameを指定します。未指定時は"test"で、例えばtest.tpldbが
作成されます。
>gen_db -rr
@u:gen_db,p:gen_db -o,n:gen_db -s
使用法: j_presto gen_db -rr RESIDUE_RENAME [RESIDUE_RENAME ...]

AMBERで定義された残基名を変更します。旧名と新名をcolonで結びます。
例: TIP3P水の"TP3"をtpldb内で"WAT"へ変更する場合
    j_presto gen_db -rr TP3:WAT
複数指定する場合:
    j_presto gen_db -rr aaa:AAA bbb:BBB ...
>gen_db -s
@u:gen_db,p:gen_db -rr
使用法: j_presto gen_db -s SOLVENT_BOX [SOLVENT_BOX ...]

*.lib内の溶媒座標からj_presto用溶媒座標database（*.slv）を作成する場合、
TIP3PBOXなどのsolvent box名を指定します。solvent box名は*.lib内で確認できます。
複数名を指定すれば、複数のslvファイルを一度に出力できます。

現在のj_prestoには圧力制御法がなく、定圧計算で溶媒密度を調整できません。そのため、
*.libから作った*.slvより、300 K・1 atmで事前平衡化したj_prestoBOX.slvの使用を
推奨します。"j_presto prep -sdb"を指定しない場合、j_prestoBOX.slvが既定で
使用されます。
>prep
@u:j_presto,p:gen_db,n:pepchk
"j_presto prep"は、入力PDB、gen_dbで作成したtopology database（*.tpldb）、
必要に応じて溶媒座標（*.slv）を使用し、シミュレーション系を準備します。

主な機能:
    指定pHに基づく一部アミノ酸の電荷状態変更
    系の一部の切り出し
    protein N末端/C末端へのACE/NME付加
    溶媒・ionの追加
    系の重心移動
    残基名変更
    SHAKE入力の作成

オプション:
    prep -o      出力basename
    prep -i      入力PDB
    prep -db     topology database
    prep -pH     pH
    prep -nah    HIS protonationの自動判定を無効化
    prep -dh     default histidine
    prep -th     HIS protonation判定のH-bond距離閾値
    prep -ts/-tc/-tr/-tb    trim形状・中心・半径・境界
    prep -pair   DNA duplex pair
    prep -ACE/-NME          protein末端cap
    prep -s/-sdb/-ss/-sh/-sp/-sc/-sr/-sb    溶媒設定
    prep -c      旧版互換の溶媒・ion追加法
    prep -mc     系の中心を原点へ移動
    prep -ia/-sd/-ie        ion名・濃度、溶媒密度、ion排除距離
    prep -rr     残基名変更
    prep -shake  SHAKE入力作成

各引数の詳細は、例えば "prep -i" を入力してください。
"j_presto get_tmpl prep"で実行scriptのtemplateを取得できます。
>prep -o
@u:prep,n:prep -i
使用法: j_presto prep -o OUTPUT

出力ファイルのbasenameを指定します。未指定時は"test"で、test.pdb、test.tplなどが
作成されます。
>prep -i
@u:prep,p:prep -o,n:prep -db
使用法: j_presto prep -i INPUT

入力PDBファイル名を指定します。
>prep -db
@u:prep,p:prep -i,n:prep -pH
使用法: j_presto prep -db TPLDB

topology database（*.tpldb）を指定します。
>prep -pH
@u:prep,p:prep -db,n:prep -nah
使用法: j_presto prep -pH PH_VALUE

系のpHを指定します。未指定時は7.0です。この値に基づいてGlu、Lysなどの
アミノ酸の電荷状態を決定します。
>prep -nah
@u:prep,p:prep -pH,n:prep -dh
使用法: j_presto prep -nah

通常、PDB中で"HIS"と記されたhistidineの状態は、系のpHと他残基とのH-bond状態から
自動判定されます。この自動判定を行わず、すべてのHISを-dhで指定したdefault
histidineにする場合、このオプションを指定します。
>prep -dh
@u:prep,p:prep -nah,n:prep -th
使用法: j_presto prep -dh DEFAULT_HIS

default histidine名（HIDまたはHIE）を指定します。-nahを指定した場合、またはpH・
H-bond解析から状態を決定できない場合、PDB中のHISをこの残基へ変換します。

@u:j_presto,p:prep,n:md_run
"j_presto pepchk"は、PDBファイル中のペプチド結合geometryを検査します。
隣接する各残基対について、次のω二面角を計算します。

    omega(i,i+1) = dihedral(CA_i, C_i, N_(i+1), CA_(i+1))

既定では、|omega| <= 30°をcis、|omega| >= 150°をtrans、それ以外をtwistedと
分類します。C_i--N_(i+1)距離が1.70 Åを超える残基対は、距離判定を無効にしない限り
ペプチド結合として扱いません。

使用法:
    j_presto pepchk INPUT.pdb [options]

オプション:
    pepchk --model                解析するMODEL recordを選択
    pepchk --csv                  全結果をCSVへ出力
    pepchk --cis-cutoff           cis角度閾値
    pepchk --trans-cutoff         trans角度閾値
    pepchk --cn-max               peptide C--N距離上限
    pepchk --ignore-cn-distance   C--N距離filterを無効化
    pepchk --include-nonstandard  主鎖原子を持つ非標準残基も解析
    pepchk --report-missing       欠損主鎖原子を報告
    pepchk --fail-on-cis          cisまたはtwisted検出時にexit status 2を返す
    pepchk --version              program versionを表示

pepchkのversionは、他のj_prestoサブプログラムとは独立に管理されます。
>pepchk --model
@u:pepchk,n:pepchk --csv
使用法:
    j_presto pepchk INPUT.pdb --model MODEL_NUMBER

解析するPDB MODEL recordを選択します。既定値はMODEL 1です。MODEL/ENDMDL recordの
ないPDBは、一つのmodelとして扱います。
>pepchk --csv
@u:pepchk,p:pepchk --model,n:pepchk --cis-cutoff
使用法:
    j_presto pepchk INPUT.pdb --csv OUTPUT.csv

検査した各残基対、C--N距離、ω角、分類結果をCSVファイルへ出力します。
>pepchk --cis-cutoff
@u:pepchk,p:pepchk --csv,n:pepchk --trans-cutoff
使用法:
    j_presto pepchk INPUT.pdb --cis-cutoff DEGREES

|omega|がこの値以下の結合をcisと分類します。既定値は30°です。
>pepchk --trans-cutoff
@u:pepchk,p:pepchk --cis-cutoff,n:pepchk --cn-max
使用法:
    j_presto pepchk INPUT.pdb --trans-cutoff DEGREES

|omega|がこの値以上の結合をtransと分類します。既定値は150°です。cisとtransの
閾値の間はtwistedと分類します。
>pepchk --cn-max

>pepchk --ignore-cn-distance

>GEPSME

>SCALET

solvent用CAP boundaryを適用する分子種を指定します。

形式:
    BOUND> INCLUDE
    WAT 1 999999 NO

第1成分はtopology fileの"TPL> MOLECULES"に記載された分子種名です。第2・第3成分は
対象分子IDの最小・最大値です。上例ではWAT 1–999999、実質すべてのwaterへ適用します。
Na+やCl-へCAPを明示しなくても、vacuum中ではenergetically unstableなためsolventにより
内側へ戻されます。第4成分をYESにすると、CAP適用分子情報をlogへ出力します。

@u:CAPbound.inp,p:BOUND> RADIUS,n:BOUND> LIST

>BOUND> LIST
@u:CAPbound.inp,p:BOUND> FORCE,n:BOUND> BUFFER
solute用CAP boundaryを適用するatomを指定します。

形式例:
    BOUND> LIST
    1 1 1 99999 C* * NO
    1 1 1 99999 N* * NO
    ...

第1・第2成分: 対象chainの最初・最後。第1成分が0以外なら、第3・第4成分は各chain内の
residue番号範囲です。第1成分が0なら、第3・第4成分はPDBに書かれた全体の連続residue
番号範囲です。
第5成分: atom名。"*"や"C*"のように末尾wildcardを使用できます。"HEAV"はH以外、
"SIDE"はprotein/nucleic acidのbackbone以外です。*Aや*C*のような先頭・中間wildcardは
使用できません。
第6成分: residue名。atom名と同様にwildcardを使用できます。
第7成分: YESで適用atom情報をlogへ出力します。

    END

第1・第2成分: 対象chain範囲。第1成分が0以外なら第3・第4成分は各chain内residue範囲、
0ならPDB全体の連続residue番号範囲です。
第5成分: atom名。末尾wildcardを使用でき、"HEAV"はH以外、"SIDE"はbackbone以外です。
第6成分: residue名（wildcard可）。
第7成分: force constant（kcal/mol）。
第8成分: MASSならforce constantへatom massを掛けます。NOMAは掛けません。
第9成分: YESで適用atom情報をlogへ出力します。
>PSR> RADIUS
@u:psr.inp,p:PSR> LIST,n:DSR> LIST
center atomから指定距離範囲にあるatomへposition restraintを適用します。

形式例:
    PSR> RADIUS
    1 5 CA 10.0 20.0 CA 1.0 NOMA NO
    ...
    END

第1–3成分: center atomのchain番号、residue番号、atom名。
第4・第5成分: rmin、rmax。
第6成分: restraint対象atom名（末尾wildcard可）。
第7成分: force constant（kcal/mol）。
第8成分: MASSならatom massを掛け、NOMAなら掛けません。
第9成分: YESで適用atom情報をlogへ出力します。
>DSR> LIST
@u:dsr.inp,p:PSR> RADIUS
dsr.inpでdistance restraintを指定します。

形式例:
    DSR> LIST
    1 1 ASN CA 1 2 LEU CA 1.0 10.0 2.0 17.0 NO
    END

二atom間距離がrmin未満またはrmax超過になった場合、それぞれforce constant fmin、fmax
（kcal/mol）のharmonic forceを加えます。
第1–4成分は第1 atomのchain、residue番号、residue名、atom名、第5–8成分は第2 atomの
同情報、第9–12成分はfmin、fmax、rmin、rmaxです。第13成分をYESにすると適用情報を
logへ出力します。
>DHR> NUMBER
@u:dhr.inp,n:DHR> LIST
dhr.inpでatom番号によりdihedral angle restraintを指定します。

形式例:
    DHR> NUMB
    1 2 3 4 10.0 10.0 40.0 80.0 NO
    END

四atomのdihedral angleがrmin未満またはrmax超過の場合、fminまたはfmax（kcal/mol）の
harmonic forceを加えます。第1–4成分はPDB atom番号、第5–8成分はfmin、fmax、rmin、
rmax（degree）、第9成分はYESで適用情報をlogへ出力します。
>DHR> LIST
@u:dhr.inp,p:DHR> NUMBER
dhr.inpでchain、residue番号、atom名によりdihedral angle restraintを指定します。

形式例:
    DHR> LIST
    1 1 N 1 CA 1 C 2 N 10.0 10.0 40.0 80.0 NO
    END

第1成分はchain番号、第2–9成分は四atomのresidue番号とatom名、第10–13成分はfmin、
fmax、rmin、rmax（degree）です。角度が範囲外になるとharmonic forceを加えます。
第14成分をYESにすると適用情報をlogへ出力します。
>batch_set
@u:j_presto,p:md_run,n:GEprep
"j_presto batch_set"は、多数のMD runを実行するための入力ファイルと実行scriptを
自動作成します。一つのMD runではmd.inpを用意して"j_presto md_run md.inp"を
実行しますが、初期速度の異なる多数runや、McMD/ALSDの反復runを手作業で準備するのは
煩雑です。batch_setは、j_presto_mpiまたはj_presto_masterで複数runを一つのMPI jobとして
実行するためのdirectory構造とfileを作成します。

実行前に次の三fileを準備します（括弧内は既定名）。
    1 : MD schedule入力（batch_set.inp または batch_set_ALSD.inp）
    2 : 単一md_run用実行script template（md_run.exe）
    3 : 複数run用実行script template（md_multi.exe）

current directoryにbatch_set.inp、md_run.exe、md_multi.exeがあれば自動使用します。
別名を使う場合は-b、-r、-mで指定します。詳細は"j_presto batch_set -h"を参照してください。

batch_setはmd* directoryを作り、その下にn1からn[NRUN]を作成します。各n*にはscheduleに
基づくmd.inpとmd_run.exeを配置します。またcurrent directoryにmd_multi_*.exeを作成し、
これを実行することでmd*内の全runを一つのMPI jobとしてまとめて実行できます。
>batch_set.inp
@u:batch_set,n:batch_set_ALSD.inp
batch_set.inpは、複数MD runの実行scheduleを定義する入力です。この内容からmd.inpと
directory構造を自動作成します。通常MD用templateは次で取得できます。
    j_presto get_tmpl batch_set.inp
ALSD用は"batch_set_ALSD.inp"を参照してください。

ファイル先頭の主な変数:
    nmd i j       作成・実行する最初と最後のMD ID（i <= j）
                  例: nmd 0 2 → md0、md1、md2を順に作成
    nrun i        各MD stageで実行する独立run数
                  例: nrun 60 → 各md*にn1–n60を作成
    nmpi i        MPI process数。j_presto_mpiでは通常nrunと同数。
                  resourceが少ない場合、j_presto_masterではnrun未満も指定可能
    temper r s    #TEMPERを各runへr–sの等間隔温度として展開
    lambda r s    #LAMBDAを各runへr–sの等間隔λとして展開
nmd、nrun、nmpiは必須です。

その後は、整数で始まり空行で終わるblockを記述します。"0" blockにはmd0以降で使う
初期設定を記述します。指定できるmd_run optionは"EXE> INPUT"、"EXE> MD"、
"EXE> OUTPUT"を参照してください。semicolon（;）以降はcommentです。

後続の"1"、"2"等のblockでは、そのMD ID以降で変更するoptionだけを記述します。
前stageの設定は継承されます。"OPTION= OFF"とすると以前の指定を解除できます。
例えばmd1でRESTAR=YES、NAMERI=../../md#PMD/n#RUN/restart.datとすると、各runは
前stageのrestartから継続します。

利用可能なplaceholder:
    #CMD       現在のMD ID
    #PMD       一つ前のMD ID
    #RUN       現在のrun ID
    #LAMBDA    lambdaで割り当てたλ
    #TEMPER    temperで割り当てた温度
    #RNDSED    random seed
    #NRUN      nrunで指定したrun数
    #NMPI      nmpiで指定したMPI process数

#RNDSEDは既定でmd0/n1に1、n2に2...と一意に割り当てられます。batch_setのrandom-seed
offset optionを使うと全seedへ一定値を加えられます。具体的な記述例はtemplateを参照してください。
>batch_set_ALSD.inp
@u:batch_set,p:batch_set.inp
ALSDの複数stageをbatch_setで準備するschedule入力です。
    j_presto get_tmpl batch_set_ALSD.inp
でtemplateを取得できます。batch_setは既定でbatch_set.inpを探すため、fileをrenameするか
"j_presto batch_set -b"で明示してください。

先頭のnmd、nrun、nmpi、temper、lambda、およびplaceholderの規則は"batch_set.inp"と同じです。
ALSD templateは概ね次の流れで構成されます。

    md0    restraint付きrelaxation
    md1    restartを使用したrelaxation
    md2    複数の固定λを用いるCLMDを実行し、dlnP(λ)/dλの初期推定を作成
    md3–md25
           ALSDを反復し、PREFITで前stageの*.nfを読みながら推定関数を更新。
           NXMAXV等でλ範囲を段階的にλ=1付近まで拡張し、FORCESも調整
    md26   production ALSD。reweighting用のλ、E_AA、E_AB範囲を設定
    md27   production結果からcanonical weight（*.prob）を作成

ALSDでは系をRegion AとRegion Bへ分け、potential energyを
    E = E_AA + E_AB + E_BB
と表します。λによりRegion A関連interactionをscaleし、
    E_ALSD = λ^2 E_AA + λ E_AB + E_BB + RT lnP(λ)
を用います。λ=1は通常MDと同等、λ<1ではRegion Aのinteractionが弱まり構造変化が
促進されます。未知のdlnP(λ)/dλをCLMDと反復ALSDから推定し、λが設定範囲をrandom walk
できるようにします。

md2ではLAMBDA=#LAMBDAにより各runへ異なる固定λを割り当て、SIMTYP=CLMDとしてGEprep用
初期dataを作ります。ALSD開始後はLAMBDA=OFFにしてください。設定したままだとrestartに
保存されたλを継承せず、毎回強制的に初期値へ戻ります。

GEprep関連optionは各MD block内にmd_run optionと一緒に記述できます。PREFITは前stageの
*.nf、INPENEはenergy/λ file pattern、NFIRST/NFINALは推定に使うdata範囲です。
production後はMINLMD/MAXLMD、MINEAA/MAXEAA、MINEAB/MAXEABを用いてλ=1 ensembleの
reweightingを行います。具体的なstage番号・計算長・λ範囲・FORCESは系に応じて調整し、
templateの値をそのまま無条件に使用しないでください。
>GEprep
@u:j_presto,p:batch_set,n:j_presto_mpi
"j_presto GEprep"は、McMDやALSDなどgeneralized-ensemble（GE）MDで使用する
parameter file（*.nf）を作成します。通常は"j_presto batch_set"が作成する
md_multi_*.exe内から自動実行されるため、直接実行する機会は多くありません。

使用法:
    j_presto GEprep GEprep.inp

GEprep.inpは通常batch_set.inpのGEprep optionから自動生成されます。

主なoption:
    PROJNM / SIMTYP / DATLST           project名、simulation type、入力data list
    MINVAL / MAXVAL / SIMTEM           sampling範囲とsimulation温度
    FITDIM / NWINDO                    spline fitting条件
    NXMINV / NXMAXV / PREFIT           次stage範囲と前stage parameter
    TMPSMP / NXTEMP                    McMD reweighting温度と次stage温度
    LAMBDA                              ALSD reweighting対象λ
    MINLMD / MAXLMD                    ALSD reweightingのλ範囲
    MINEAA / MAXEAA                    Region A energy範囲
    MINEAB / MAXEAB                    Region A–B energy範囲
    NBNLMD / SBNEAA / SBNEAB           reweighting histogramのbin設定
    FORCES / ADJENE                    λ境界force、energy範囲自動調整
    INPENE / NFIRST / NFINAL           function推定に使う*.eneとdata範囲

McMDではpotential energy Eを低energyから高energyまでrandom walkさせます。
    E_McMD = E + RT lnP(E)
    F_McMD = F + RT dlnP(E)/dE
ALSDではRegion A関連energyをλでscaleします。
    E = E_AA + E_AB + E_BB
    E_ALSD = λ^2 E_AA + λ E_AB + E_BB + RT lnP(λ)
    F_ALSD(atom) = λ^2 F_AA + λ F_AB + F_BB
    F_ALSD(λ) = -2 E_AA λ - E_AB - RT dlnP(λ)/dλ
未知のdlnP(E)/dEまたはdlnP(λ)/dλを反復計算dataから推定し、polynomial splineでfitします。

主要出力:
    *.nf       次のMcMD/ALSD runで入力するfunction parameter
    *.prob     canonical ensemble再構成用weight
    *.bar      TTP各runが探索したEまたはλ範囲
    *.dist     lnP(E)またはlnP(λ)。指定範囲内でflatかを確認
    *.dlnN     McMDのraw/fitted dlnP(E)/dE
    *.dlnP     ALSDのraw/fitted dlnP(λ)/dλ
    *.cdist    McMDのreweighted canonical lnP(E)
    *.edist    ALSD各trajectoryのlnP(λ)
    *.cprob    ALSD reweightingのE_AA–E_AB canonical分布
    *.ene      入力energy/λ data

*.distがflatでない、または*.dlnN/*.dlnPのraw dataとfitが大きくずれる場合、FITDIM、NWINDO、
NXMINV、NXMAXV、FORCESを再検討してください。
>PROJNM
@u:GEprep,n:SIMTYP
GEprep.inpで、出力ファイルのproject名（basename）を指定します。
例: PROJNM=testならtest.nf、test.prob等を出力します。
>SIMTYP
@u:GEprep,p:PROJNM,n:DATLST
GEprep.inpでsimulation typeを指定します。主な値:
    CANO    canonical MD data
    MULT    McMD
    CLMD    constant-lambda MD
    ALSD    adaptive lambda square dynamics
選択により、推定するfunctionと出力形式が変わります。
>DATLST
@u:GEprep,p:SIMTYP,n:MINVAL
GEprepがMcMD/ALSD functionを推定するために読み込むenergy・lambda data fileのlistを
指定します。通常はbatch_setとgenlistがfile.listを自動作成します。
>MINVAL
@u:GEprep,p:DATLST,n:MAXVAL
GEprep.inpで、現在のMcMD energyまたはALSD λ sampling範囲の下限を指定します。
>MAXVAL
@u:GEprep,p:MINVAL,n:SIMTEM
GEprep.inpで、現在のMcMD energyまたはALSD λ sampling範囲の上限を指定します。
>SIMTEM
@u:GEprep,p:MAXVAL,n:FITDIM
GEprep.inpで、入力simulation dataを生成した温度を指定します。
>FITDIM
@u:GEprep,p:SIMTEM,n:NWINDO
McMDのdlnP(E)/dEまたはALSDのdlnP(λ)/dλをfitするpolynomial splineの次数を指定します。
次数を上げるとfit誤差は小さくなりますが、overfittingや外挿時の振動を起こしやすくなります。
通常2–6を推奨し、反復初期は2程度、functionが安定した後に4–6へ上げます。

*.distで探索分布、*.dlnNまたは*.dlnPでraw functionとfitを確認してください。fit誤差が
大きい場合、次数を過度に上げるよりNWINDOを増やす方法も検討してください。
>NWINDO
@u:GEprep,p:FITDIM,n:NXMINV
McMD/ALSD functionをpolynomial spline fitするwindow数を指定します。windowを増やすと
各領域を局所的にfitでき、複雑なfunctionへ対応しやすくなります。ただしdataの少ないwindowを
作りすぎるとfitが不安定になります。*.dist、*.dlnN、*.dlnPを確認して調整してください。
>NXMINV
@u:GEprep,p:NWINDO,n:NXMAXV
次のMcMD/ALSD stageで使用するsampling範囲下限を指定します。通常、初期は高energyまたは
低λ領域で構造変化を促進し、反復とともに低energyまたは高λ側へ範囲を拡張します。
現在のMINVALから大きく変えるとfit functionの外挿が悪化し、異常終了や分布の非flat化を
起こす場合があります。その場合は変化幅を小さくしてください。
>NXMAXV
@u:GEprep,p:NXMINV,n:PREFIT
次のMcMD/ALSD stageで使用するsampling範囲上限を指定します。現在のMAXVALから大きく
変えるとfit functionの外挿が悪化し、異常終了や分布の非flat化を起こす場合があります。
範囲は段階的に拡張してください。
>PREFIT
@u:GEprep,p:NXMAXV,n:TMPSMP
現在のMcMD/ALSD stageで使用したfunction parameter file（*.nf）を指定します。初期functionは
canonical MDまたはCLMDから推定し、後続stageではPREFITの*.nfと新しいE/λ dataを合わせて、
次stage用functionを更新します。
>TMPSMP
@u:GEprep,p:PREFIT,n:NXTEMP
McMD結果からreweightingによって再構成するcanonical ensembleの温度を指定します。
McMDは広いenergy範囲を探索するため、得られたensembleから任意温度のensembleを再構成できます。
>NXTEMP
@u:GEprep,p:TMPSMP,n:GEprep LAMBDA
次のMcMD stageで使用するsimulation温度を指定します。現在のSIMTEMから変更する場合に使用します。
>GEprep LAMBDA
@u:GEprep,p:NXTEMP,n:MINLMD
ALSD結果をreweightingして再構成するensembleのλを指定します。既定値は1.0です。
通常、λ≠1のensembleに直接の物理的意味はないため、特別な目的がなければ設定不要です。
>MINLMD
@u:GEprep,p:GEprep LAMBDA,n:MAXLMD
ALSD reweightingで使用するλ範囲の下限を指定します。λ=1 canonical ensembleの再構成に
必要な幅を含めます。範囲を広げすぎると三次元histogramのmemory使用量が増えます。
>MAXLMD
@u:GEprep,p:MINLMD,n:MINEAA
ALSD reweightingで使用するλ範囲の上限を指定します。MINLMDと合わせ、通常λ=1を中心に
必要な幅を設定します。
>MINEAA
@u:GEprep,p:MAXLMD,n:MAXEAA
ALSD reweightingで使用するRegion A内部energy E_AAの下限を指定します。適切な範囲はGEprep
logに表示される選択λ範囲内のmin/maxを参考にします。ADJENE=YESで自動決定できます。
>MAXEAA
@u:GEprep,p:MINEAA,n:MINEAB
ALSD reweightingで使用するRegion A内部energy E_AAの上限を指定します。範囲を広げすぎると
memory使用量が増え、狭すぎると必要dataを失います。ADJENE=YESで自動決定できます。
>MINEAB
@u:GEprep,p:MAXEAA,n:MAXEAB
ALSD reweightingで使用するRegion A–B間energy E_ABの下限を指定します。GEprep logを参考に
設定するか、ADJENE=YESで自動決定します。
>MAXEAB
@u:GEprep,p:MINEAB,n:NBNLMD
ALSD reweightingで使用するRegion A–B間energy E_ABの上限を指定します。GEprep logを参考に
設定するか、ADJENE=YESで自動決定します。
>NBNLMD
@u:GEprep,p:MAXEAB,n:SBNEAA
ALSD reweightingのλ方向bin数を指定します。既定値は20です。λ、E_AA、E_ABの三次元
histogramを保持するため、値を小さくするとmemoryを削減できます。ただし通常はNBNLMDを
減らす前にSBNEAAまたはSBNEABを大きくすることを推奨します。
>SBNEAA
@u:GEprep,p:NBNLMD,n:SBNEAB
ALSD reweightingのE_AA方向energy bin幅を指定します。既定値は1.0です。値を大きくすると
memoryを削減できますが、同一bin内の全構造へ同じweightを与えるため、過度に大きい値は
reweighted ensembleの精度を低下させます。
>SBNEAB
@u:GEprep,p:SBNEAA,n:ADJENE
ALSD reweightingのE_AB方向energy bin幅を指定します。既定値は1.0です。値を大きくすると
memoryを削減できますが、過度に大きい値はreweighting精度を低下させます。
>ADJENE
@u:GEprep,p:FORCES,n:INPENE
ADJENE=YESとすると、ALSD reweightingのMINEAA、MAXEAA、MINEAB、MAXEABを入力dataから
自動決定します。既定値はNOです。範囲決定のため一度全energy dataを読み、その後同じdataを
再度読み込んでreweightingするため、計算時間は概ね二倍になります。

手動設定する場合、まずMINLMD/MAXLMDを定め、暫定energy範囲でGEprepを実行します。logの
"min & max EAA & EAB"を基に範囲を更新して再実行します。ADJENE=YESはこの作業を自動化します。
>FORCES
@u:GEprep,p:MAXEAB,n:ADJENE
λ particleがMINVAL–MAXVAL範囲外へ出た場合、範囲内へ戻すforceの大きさを指定します。
目安としてλ particle massの半分程度が有効です。λ massは既定でRegion A atomの総質量で、
md_run logの"LAMBDA WEIGHT"に表示されます。

小さすぎるとλが範囲から大きく外れ、計算不安定化や異常終了を起こします。大きすぎると
境界付近のλ方向forceが過大になり、低λでfoldしようとする構造を高λへ押し戻してsamplingを
妨げる可能性があります。反復初期はdlnP(λ)/dλの精度が低いため大きめに設定し、推定が
安定するにつれて最終目標値まで段階的に下げる方法を推奨します。
>INPENE
@u:GEprep,p:ADJENE,n:NFIRST
batch_set.inpでMcMD/ALSD反復runを準備する際、function推定に使用する*.ene file patternを
指定します。内部で"j_presto genlist"を実行し、該当pathを含むfile.listを自動作成します。
#RUN等のplaceholderを使用できます。genlist -rのdata範囲はNFIRSTとNFINALから与えられます。
>NFIRST
@u:GEprep,p:INPENE,n:NFINAL
McMD/ALSD function推定へ使用する*.ene dataの最初のdata point番号を指定します。各stageは
前stageからrestartするため、初期部分には前のfunctionの影響が残ることがあります。例えば
最初の100000 stepを除外する場合、NFIRST=100001とします。
>NFINAL
@u:GEprep,p:NFIRST
McMD/ALSD function推定へ使用する*.ene dataの最後のdata point番号を指定します。file末尾まで
すべて使う場合は、実data数より十分大きい値を指定します。
>j_presto_mpi
@u:j_presto,p:GEprep,n:j_presto_master
複数のMD runをembarrassingly parallel方式で一つのMPI jobとして実行します。MPI起動commandは
環境によりmpirun、mpiexec、mpiexec.hydra等が異なります。例:
    mpiexec.hydra j_presto_mpi MD_ID NUMBER_OF_RUNS NUMBER_OF_MPI_PROCESSES

batch_setを使う場合、まず
    j_presto get_tmpl md_multi
でmd_multi.exe templateを取得し、job scheduler（PBS/Torque、NQSII/Fugaku、SLURM、LSF等）の
header、MPI起動command、OMP_NUM_THREADSを環境に合わせて変更します。templateには
j_presto_mpiとj_presto_masterの両方が含まれるため、使用しない方をcomment outまたは削除します。
batch_setはこのtemplateから各MD ID用md_multi_*.exeを自動作成します。
>j_presto_master
@u:j_presto,p:j_presto_mpi,n:traj_conv
複数のMD runをmaster-worker方式で一つのMPI jobとして実行します。MPI process数がrun数より
少ない場合、masterが未実行runをworkerへ順次割り当てます。例:
    mpiexec.hydra j_presto_master MD_ID NUMBER_OF_RUNS NUMBER_OF_MPI_PROCESSES

"j_presto get_tmpl md_multi"でtemplateを取得し、scheduler header、MPI起動command、
OMP_NUM_THREADSを使用環境に合わせて変更してください。templateにはj_presto_mpiと
j_presto_masterの両方があるため、使用しない方をcomment outまたは削除します。batch_setは
このtemplateからmd_multi_*.exeを作成します。
>traj_conv
@u:j_presto,p:j_presto_master,n:Ens_Ana
"j_presto traj_conv"は、j_prestoのCOD/CODS形式とMDAnalysisが対応する構造・トラジェクトリ形式の間で変換を行います。入力・出力形式はファイル拡張子から自動判定されます。

使用法:
    j_presto traj_conv -i INPUT -r REFERENCE.pdb -o OUTPUT [options]

参照PDBは原子の種類と順序を定義します。変換時には、原子選択、frame範囲、strideを指定できます。COD/CODSの読み書きはtraj_conv内部で行われ、その他の形式にはMDAnalysisが必要です。

必須option:
    traj_conv -i    入力構造またはトラジェクトリ
    traj_conv -r    参照PDB
    traj_conv -o    出力構造またはトラジェクトリ

その他のoption:
    traj_conv -b    最初のframe（1始まり、指定frameを含む）
    traj_conv -e    最後のframe（指定frameを含む）、またはEND
    traj_conv -s    frame stride
    traj_conv -as   atom specifier
    traj_conv -p    周期境界処理
    traj_conv -op   同時出力する参照PDBのファイル名
    traj_conv -c    ファイルを書かずに入力・変換条件を検査
    traj_conv -f    既存出力ファイルの上書きを許可
    traj_conv -v    traj_convのversionを表示
>traj_conv -i
@u:traj_conv,n:traj_conv -r
使用法:
    j_presto traj_conv -i INPUT

入力する構造またはトラジェクトリを指定します。形式は拡張子から判定されます。COD/CODSは直接読み込み、それ以外の形式はMDAnalysisを介して読み込みます。
>traj_conv -r
@u:traj_conv,p:traj_conv -i,n:traj_conv -o
使用法:
    j_presto traj_conv -r REFERENCE.pdb

原子の種類と順序を与える参照PDBを指定します。atom selectionを適用する前の原子数が、入力トラジェクトリと整合している必要があります。
>traj_conv -o
@u:traj_conv,p:traj_conv -r,n:traj_conv -b
使用法:
    j_presto traj_conv -o OUTPUT

出力ファイルを指定します。出力形式は拡張子から判定されます。既存ファイルを上書きする場合は-f/--forceを指定してください。
>traj_conv -b
@u:traj_conv,p:traj_conv -o,n:traj_conv -e
使用法:
    j_presto traj_conv -b FIRST_FRAME

出力を開始する入力frameを指定します。frame番号は1始まりで、指定frameを含みます。defaultは1です。
>traj_conv -e
@u:traj_conv,p:traj_conv -b,n:traj_conv -s
使用法:
    j_presto traj_conv -e LAST_FRAME

出力する最後の入力frameを指定します。frame番号は1始まりで、指定frameを含みます。ENDを指定するか、このoptionを省略すると最終frameまで処理します。
>traj_conv -s
@u:traj_conv,p:traj_conv -e,n:traj_conv -as
使用法:
    j_presto traj_conv -s STRIDE

-bで指定したframeから、STRIDE frameごとに出力します。defaultは1です。
>traj_conv -as
@u:traj_conv,p:traj_conv -s,n:traj_conv -p
使用法:
    j_presto traj_conv -as 'ATOM_SPECIFIER'

共通のj_presto atom specifierを用いて、変換対象とする原子集合を指定します。defaultは"*"（全原子）です。shellによる解釈を避けるため、式は引用符で囲んでください。詳細は"atom specifier"を参照してください。
>traj_conv -p
@u:traj_conv,p:traj_conv -as,n:traj_conv -op
使用法:
    j_presto traj_conv -p {none,nojump,unwrap}

COD以外の入力に対する周期境界処理を指定します。
    none      入力座標をそのまま保持します。
    nojump    frame間で周期境界を横切る座標jumpを除去します。
    unwrap    結合情報に基づいて、周期境界をまたぐ分子を再構成します。

defaultはnoneです。unwrapには参照PDB中の結合情報が必要です。
>traj_conv -op
@u:traj_conv,p:traj_conv -p,n:traj_conv -c
使用法:
    j_presto traj_conv -op OUTPUT_REFERENCE.pdb

選択された原子のみを含む付随PDBを出力します。COD/CODSを出力する場合、入力ファイルを上書きする危険がない限り、defaultで付随PDBも作成されます。
>traj_conv -c
@u:traj_conv,p:traj_conv -op,n:traj_conv -f
使用法:
    j_presto traj_conv ... -c

出力ファイルを作成せず、指定された変換、frame範囲、原子選択、出力形式の整合性を検査します。
>traj_conv -f
@u:traj_conv,p:traj_conv -c,n:traj_conv -v
使用法:
    j_presto traj_conv ... -f

既存の出力ファイルを上書きすることを許可します。このoptionを指定しない場合、既存ファイルを置き換えずに停止します。
>traj_conv -v
@u:traj_conv,p:traj_conv -f
使用法:
    j_presto traj_conv -v

独立管理されているtraj_convのversionを表示して終了します。
>md_multi.exe
@u:batch_set
md_multi.exeは、"j_presto batch_set"で準備した複数のMD runを一つのMPI jobとして実行するためのscriptです。templateは次のcommandで取得できます。
    j_presto get_tmpl md_multi

取得後、使用する計算機環境に合わせて編集してください。このscriptはj_presto_mpiまたはj_presto_masterを起動します。MPI起動commandは環境によってmpirun、mpiexec、mpiexec.hydraなどが異なります。例:
    mpiexec.hydra (j_presto_mpi or j_presto_master) [MD ID] [MD run数] [MPI process数]

PBS/Torque、NQSII/Fugaku、SLURM、LSF等のjob schedulerに応じて、qsub、pjsub、sbatch、bsub用の指定を追加し、OpenMP thread数（例: export OMP_NUM_THREADS=8）も調整してください。詳細は利用する計算機のparallel job実行manualを参照してください。

templateにはj_presto_mpi用とj_presto_master用の両方が含まれます。使用しない方を#でcomment outするか削除してください。batch_setは編集済みtemplateを用いて、MD IDごとのmd_multi_*.exeを自動生成します。
>Ens_Ana
@u:j_presto,p:traj_conv,n:DISTIL
"j_presto Ens_Ana"は、simulation結果から得られた構造ensembleを解析します。
使用法:
    j_presto Ens_Ana [input filename]

解析条件は入力ファイルEns_Ana.inpで指定します。templateは次のcommandで取得できます。
    j_presto get_tmpl Ens_Ana.inp
実行scriptのtemplateは次で取得できます。
    j_presto get_tmpl Ens_Ana
各設定の詳細は"Ens_Ana.inp"および個別option項目を参照してください。

主な出力ファイル:
    *_ave.pdb    ensemble平均構造。
    *_con.pdb    atom_spec_contactで指定したtarget原子の接触確率をB-factorへ記録。
    *_dist.dx    選択原子群の空間分布（OpenDX形式）。
    *_dist.xplor 選択原子群の空間分布（Xplor形式）。
    *_RMSF.pdb   各原子のRMSFをB-factorへ記録。
    *.cod        j_presto binary座標形式。
    *.distan     選択原子間の距離。column 1はGEPS weight（通常MDでは1）、column 2以降は各距離。
    *.PCAcod     PCAaxis/PCAprojへ入力するbinary PCA座標。
    *.Qval       Q value。column 1:構造番号、2:weight、3:Q value。
    *.Rg         回転半径。column 1:構造番号、2:Rg、3:重心から最遠原子までの距離、4:weight。
    *.rmsd       参照構造に対するRMSD。column 1:構造番号、2:RMSD、3:weight。
    *.SS         DSSPが割り当てた各残基の二次構造（H, B, E, G, I, T, S, 空白）。
    *.sscr       各残基における二次構造の出現確率。
    *.sscs       各構造に含まれる各二次構造の残基数。
    *.sscw       ensemble全体における二次構造の割合。
    *.TTPncnf    各simulation runから出力された構造数。distribでrun間標準誤差を計算する際に使用。
    *.weight     各構造のweight、lambda、energy。column 1:構造番号、2:weight、3:lambda、4:全potential energy、5:EAA、6:EAB、7:EBB。

詳細はoption名をmanualで検索してください。
>overwrite_flag
@u:Ens_Ana.inp,n:project_name
Ens_Anaが同名の解析結果を出力する場合の上書きを制御します。
    overwrite_flag = YES    既存ファイルを確認せず上書き
    overwrite_flag = NO     上書きしない（default）
>project_name
@u:Ens_Ana.inp,p:overwrite_flag,n:log_level
解析project名と出力名を指定します。defaultは"a"です。
例えば"project_name = test"では、実行directoryに"Ens_Ana_test"が作成され、解析結果がその中へ保存されます。
>log_level
@u:Ens_Ana.inp,p:project_name,n:template_PDB
Ens_Anaのlog出力量を指定します。
    log_level = long     詳細log
    log_level = short    簡略log
    log_level = no       logを出力しない（default）
>template_PDB
@u:Ens_Ana.inp,p:log_level,n:input_topology
解析対象systemのPDBを指定します。原子名、残基名等の情報はこのPDBから取得されます。input_binary_listを使用する場合、原子数と原子順序がCODと一致する必要があります。md_runのOUTATMで一部原子だけを出力した場合、ここで指定するPDBも同じ原子集合・順序にしてください。
>input_topology
@u:Ens_Ana.inp,p:template_PDB,n:input_PDB_list
解析に原子chargeやvan der Waals半径が必要な場合、topology file (*.tpl)を指定します。tplは"j_presto prep"で作成できます。Q value、contact、distribution等の解析で使用されます。
>input_PDB_list
@u:Ens_Ana.inp,p:input_topology,n:PDB_consistency_check
解析するPDBファイル名を一行に一つ記載したlist fileを指定します。例:
    1.pdb
    2.pdb
    3.pdb
Ens_Anaは、このlistに含まれる複数構造を一つのensembleとして解析します。
>PDB_consistency_check
@u:Ens_Ana.inp,p:input_PDB_list,n:input_binary_list
input_PDB_listおよび参照PDBがtemplate_PDBと整合しているかを検査します。defaultはYESです。検査には計算時間を要するため、整合性を別途確認済みの場合のみNOにできます。
>input_binary_list
@u:Ens_Ana.inp,p:PDB_consistency_check,n:output_PDB_flag
解析するj_presto binary座標ファイル（*.cod）のlistを指定します。各fileについて、file名と解析する構造番号範囲を2行で記載します。例:
    1.cod
    51  99999999
    2.cod
    51  99999999

上例では各fileの最初の50構造を除外し、51番目以降を解析します。終端番号が実際の構造数を超える場合は最終構造まで使用します。

分割して実行したtrajectoryを連続trajectoryとして扱う場合、前segmentのfile名末尾に" ->"を付けます。例:
    1.cod ->
    51  99999999
    2.cod
    51  99999999
これは時系列解析で有用です。

CODはmd_runのNAMECOで出力します。OUTATMで一部原子だけを出力した場合、template_PDBも対応する原子だけを同じ順序で含めてください。
>output_PDB_flag
@u:Ens_Ana.inp,p:input_binary_list,n:output_binary_flag
YESにすると入力構造をPDBとして出力します。例えばproject_name=testでは、"Ens_Ana_test/test_PDB/1.pdb"等へ保存されます。CODからPDBへの変換や、RMSD fitting後の構造出力に使用できます。入力構造数が多い場合は大量のfileが作成される点に注意してください。
>output_binary_flag
@u:Ens_Ana.inp,p:output_PDB_flag,n:reference_PDB
入力構造をj_presto binary座標形式（*.cod）として出力します。
>reference_PDB
@u:Ens_Ana.inp,p:output_binary_flag,n:input_reference_PDB_list
RMSDおよびQ value解析に使用する参照PDBを指定します。
>input_reference_PDB_list
@u:Ens_Ana.inp,p:reference_PDB,n:input_reference_binary_list
複数の参照PDBを使用する場合、そのfile名を一行に一つ記載したlistを指定します。NMR model等の複数参照構造に対するRMSD計算や、複数参照構造からNCPを定義するQ value解析に使用します。
>input_reference_binary_list
@u:Ens_Ana.inp,p:input_reference_PDB_list,n:atom_spec_output
複数の参照構造をCODで入力する場合、そのlistを指定します。形式はinput_binary_listと同様に、file名と構造番号範囲を2行で記載します。RMSDやQ valueの複数参照構造に使用できます。OUTATMで部分座標を出力した場合は、template_PDBも対応する原子だけを含めてください。
>atom_spec_output
@u:Ens_Ana.inp,p:input_reference_binary_list,n:interval
output_PDB_flag/output_binary_flagで出力する原子、およびDSSPへ渡す原子をatom specifierで指定します。書式は"atom specifier"を参照してください。
>interval
@u:Ens_Ana.inp,p:atom_spec_output,n:input_prob_file
解析に使用する入力構造の間隔を指定します。defaultは1（全構造）です。例えば"interval = 50"では50構造ごとに一つを解析します。
>input_prob_file
@u:Ens_Ana.inp,p:interval,n:weight_method
McMDやALSD等のGE simulationで各構造の出現確率を考慮する場合、weightを含むprobability file (*.prob)を指定します。このfileは"j_presto GEprep"で作成できます。
>weight_method
@u:Ens_Ana.inp,p:input_prob_file,n:weight_threshold
GE ensembleのweightを解析へ反映する方法を指定します。
    weight  各構造の出現確率をsample weightとして使用します。精密ですが計算量が増えます。
    select  0～1の乱数と出現確率を比較して構造をaccept/rejectし、重みを反映したsubensembleを作ります。
selectで使用する乱数seedはrandom_seedで指定します。
>weight_threshold
@u:Ens_Ana.inp,p:weight_method,n:random_seed
weight_method=weightのとき、McMD/ALSD構造の出現確率がこの値未満なら解析から除外します。寄与が極端に小さい構造を除き計算を高速化できます。defaultは0.00001です。
>random_seed
@u:Ens_Ana.inp,p:weight_threshold,n:input_energy_file
weight_method=selectで構造を選択する乱数seedを指定します。defaultは999999です。
>input_energy_file
@u:Ens_Ana.inp,p:random_seed,n:periodic_boundary
input_PDB_listからGE simulation構造を入力する場合、各構造のenergyを同じ順序で一行ずつ記載したfileを指定します。COD入力ではenergy情報が内部に含まれるため通常不要です。McMDでは各行にsystem全体のenergyを1値、ALSDではEAAとEABの2値を記載します。
>periodic_boundary
@u:Ens_Ana.inp,p:input_energy_file,n:DSSP_flag
入力構造が周期境界条件を用いる場合、直方体cellの下限・上限を指定します。
    periodic_boundary = [xmin:xmax,ymin:ymax,zmin:zmax]
角括弧内に空白を入れないでください。j_prestoでは直方体cellのみ対応します。
>DSSP_flag
@u:Ens_Ana.inp,p:periodic_boundary,n:atom_spec_Rg
外部program mkdsspが実行可能な場合、Ens_Anaから二次構造解析を行えます。mkdsspの導入・利用はユーザーの責任で行ってください。
    DSSP_flag = no       実行しない（default）
    DSSP_flag = yes      各構造をPDBへ変換してmkdsspを実行し、中間*.dsspは解析後に削除
    DSSP_flag = output   mkdsspを実行し、*.dsspも保持

多数の構造ではPDB出力とmkdssp実行に時間とdisk容量を要します。主な結果は*.SS、*.sscs、*.sscr、*.sscwです。
>atom_spec_Rg
@u:Ens_Ana.inp,p:DSSP_flag,n:atom_spec_RMSD
回転半径（Rg）の計算に使用する原子をatom specifierで指定します。書式は"atom specifier"を参照してください。
>atom_spec_RMSD
@u:Ens_Ana.inp,p:atom_spec_Rg,n:atom_spec_RMSD_fit
入力構造側でRMSD値の計算に使用する原子をatom specifierで指定します。fitting領域を別にする場合はatom_spec_RMSD_fitを指定します。参照構造側の対応領域はatom_spec_RMSD_ref、参照構造側のfitting領域はatom_spec_RMSD_reffitで指定できます。
>atom_spec_RMSD_fit
@u:Ens_Ana.inp,p:atom_spec_RMSD,n:atom_spec_RMSD_ref
入力構造を重ね合わせる際に使用する原子をatom specifierで指定します。RMSD値を計算する領域はatom_spec_RMSDで指定します。参照構造側の領域はatom_spec_RMSD_refとatom_spec_RMSD_reffitで指定できます。
>atom_spec_RMSD_ref
@u:Ens_Ana.inp,p:atom_spec_RMSD_fit,n:atom_spec_RMSD_reffit
参照構造側でRMSD値の計算に使用する原子をatom specifierで指定します。入力構造側はatom_spec_RMSD、参照構造側のfitting領域はatom_spec_RMSD_reffitで指定します。
>atom_spec_RMSD_reffit
@u:Ens_Ana.inp,p:atom_spec_RMSD_ref,n:RMSD_mode
参照構造側で重ね合わせに使用する原子をatom specifierで指定します。参照構造側のRMSD計算領域はatom_spec_RMSD_refで指定します。
>RMSD_mode
@u:Ens_Ana.inp,p:atom_spec_RMSD_reffit,n:interval_for_timeseries_RMSD
複数の参照構造を入力した場合のRMSD計算方法を指定します。
    RMSD_mode = average  参照構造の平均構造を作り、それに対するRMSDを計算
    RMSD_mode = multi    各参照構造に対して個別にRMSDを計算
>interval_for_timeseries_RMSD
@u:Ens_Ana.inp,p:RMSD_mode,n:RMSF_flag
trajectory中の時間変化を評価するため、現在構造と何frame前の構造とのRMSDを計算するか指定します。例えば5では、各構造と5構造前とのRMSDを計算します。
>RMSF_flag
@u:Ens_Ana.inp,p:interval_for_timeseries_RMSD,n:PCA_method
参照構造に対する入力ensembleのRoot Mean Square Fluctuation（RMSF）を計算する場合、"RMSF_flag = yes"を指定します。
>PCA_method
@u:Ens_Ana.inp,p:RMSF_flag,n:atom_spec_PCA
PCAへ使用する構造表現を指定します。対象原子はatom_spec_PCAで指定します。

残基based internal coordinate:
    average  2残基間の全原子pair距離の平均
    min      2残基間の最小原子距離
    max      2残基間の最大原子距離
    contact  接触なら1、非接触なら0。閾値はtolerance_PCA
N残基では最大N(N-1)/2次元です。neighbor_residue_PCAでsequence上近い残基pairを除外できます。大きな構造変化を含むMcMD/ALSD ensembleではCartesian座標より有効な場合があります。

原子based:
    cord       選択したN原子のCartesian座標（3N次元）
    intercord  選択したN原子の全pair距離（N(N-1)/2次元）

出力*.PCAcodはPCAaxisによる軸計算、PCAprojによる射影に使用します。
>atom_spec_PCA
@u:Ens_Ana.inp,p:PCA_method,n:neighbor_residue_PCA
PCA用構造表現へ使用する原子をatom specifierで指定します。書式は"atom specifier"を参照してください。
>neighbor_residue_PCA
@u:Ens_Ana.inp,p:atom_spec_PCA,n:tolerance_PCA
残基pair距離を用いるPCA_methodで、sequence上近い残基pairを構造表現から除外します。例えば2では各残基からsequence上2残基以内のpairを除きます。次元数と計算量を削減できます。defaultは1です。
>tolerance_PCA
@u:Ens_Ana.inp,p:neighbor_residue_PCA,n:atom_spec_Qvalue
PCA_method=contactで残基間接触を判定する距離閾値です。input_topologyがある場合は原子vdW半径の和にこの値を加え、defaultは2.8 Åです。topologyがない場合は単純な原子間距離閾値となり、defaultは6.0 Åです。
>atom_spec_Qvalue
@u:Ens_Ana.inp,p:tolerance_PCA,n:neighbor_residue_Qvalue
Q value（native contact pair再現率）解析に使用する原子をatom specifierで指定します。
>neighbor_residue_Qvalue
@u:Ens_Ana.inp,p:atom_spec_Qvalue,n:tolerance_Qvalue
Q value解析でNCP候補から除外するsequence近接残基範囲を指定します。例えば2ではsequence上2残基以内のpairをNCPに含めません。構造変化によらず接触しやすい隣接残基によるQ valueの過大評価を防ぎます。
>tolerance_Qvalue
@u:Ens_Ana.inp,p:neighbor_residue_Qvalue,n:tolerance_NCP
入力構造でNCPが再現されたと判断する距離閾値です。topologyがある場合、残基間最小原子距離がvdW半径の和＋指定値以内なら再現とし、defaultは2.8 Åです。topologyがない場合は単純距離閾値でdefaultは6.0 Åです。
>tolerance_NCP
@u:Ens_Ana.inp,p:tolerance_Qvalue,n:NCP_rate
参照構造からNative Contact Pair（NCP）を定義する距離閾値です。topologyがある場合、残基間最小原子距離がvdW半径の和＋指定値以内ならNCPとし、defaultは2.8 Åです。topologyがない場合は単純距離閾値でdefaultは6.0 Åです。
>NCP_rate
@u:Ens_Ana.inp,p:tolerance_NCP,n:cell_boundary
複数参照構造からNCPを定義する際、何割以上の参照構造で接触しているpairを採用するか指定します。defaultは0.7です。
>cell_boundary
@u:Ens_Ana.inp,p:NCP_rate,n:atom_spec_distribution
distribution解析で使用する直方体grid範囲を指定します。
    cell_boundary = [xmin:xmax,ymin:ymax,zmin:zmax]
角括弧内に空白を入れないでください。
>atom_spec_distribution
@u:Ens_Ana.inp,p:cell_boundary,n:distribution_cell_size
空間distributionを解析する原子群をatom specifierで指定します。
>distribution_cell_size
@u:Ens_Ana.inp,p:atom_spec_distribution,n:atom_spec_contact
cell_boundaryで指定した領域を分割するgrid cell sizeを指定します。小さくすると空間分解能は高くなりますが、計算時間とmemory使用量が増えます。
>atom_spec_contact
@u:Ens_Ana.inp,p:distribution_cell_size,n:tolerance_contact
contact解析のprobe原子群とtarget原子群を次の形式で指定します。
    atom_spec_contact = [probe atom specifier]_[target atom specifier]
2つのspecifierはunderscore（_）で連結します。各target原子がprobe群のいずれかの原子と接触する確率を計算します。
>tolerance_contact
@u:Ens_Ana.inp,p:atom_spec_contact,n:measurements
atom_spec_contactで指定したprobe/target間の接触判定閾値です。2原子の距離が、両原子半径の和＋この値以内なら接触と判定します。input_topologyがあればvdW半径を使用し、なければ原子種別default半径を使用します。defaultは2.8 Åです。
>measurements
@u:Ens_Ana.inp,p:tolerance_contact
指定原子の距離、角度、二面角を測定します。複数項目はsemicolonで区切り、空白を入れません。
    measurements = [metric1];[metric2];...
各metricはatom specifierをunderscore（_）で連結します。
    A_B       A-B距離
    A_B_C     A-B-C角度
    A_B_C_D   A-B-C-D二面角
atom specifierの詳細は"atom specifier"を参照してください。
>DISTIL
@u:j_presto,p:Ens_Ana,n:PCAaxis
DISTIL（Distribution-aware, Inter-region-Structured, Transformation-Invariant Learning）は、二つの分子構造ensembleを比較し、両者を識別する距離分布差を検出・解釈します。相関する距離特徴をbundleへまとめ、差を説明する構造領域pairとしてrankingします。

使用法:
    j_presto DISTIL -A ENSEMBLE_A -B ENSEMBLE_B -r REFERENCE.pdb -o OUTPUT_DIR [options]

入力ensembleにはCOD、CODS、またはlist fileを使用できます。A/Bに別々の参照PDB、topology、probability file、atom selectionを指定できます。defaultはstandard modeです。独立run間変動と比較して弱い差を評価する場合はCED modeを使用します。

manual項目:
    DISTIL input
    DISTIL weighting
    DISTIL atom selection
    DISTIL feature generation
    DISTIL standard mode
    DISTIL CED mode
    DISTIL bundling and regions
    DISTIL output
    DISTIL output main results
    DISTIL output feature and bundle tables
    DISTIL output visualization files
    DISTIL output metadata and optional analyses
    DISTIL cache and restart
    DISTIL examples
    DISTIL advanced options

性能調整・診断を含む全optionは次で確認してください。
    j_presto DISTIL -h
DISTILのversionは他のj_presto programとは独立して管理されます。

>DISTIL input
@u:DISTIL,n:DISTIL weighting
主要入力option:
    -A, --ensembleA FILE      ensemble A（COD、CODS、またはlist）
    -B, --ensembleB FILE      ensemble B（COD、CODS、またはlist）
    -fs, --frame-stride N     list範囲適用後にN frameごとに使用
    -r, --ref PDB             A/B共通参照PDB
    -rA, --refA PDB           A用参照PDB（-rより優先）
    -rB, --refB PDB           B用参照PDB（-rより優先）
    -o, --outdir DIR          出力directory（default: distil_out）

A/Bで選択される原子は、化学的・構造的に対応している必要があります。別々の参照PDBを使用する場合、DISTILは選択原子の対応を検査してから比較します。
>DISTIL weighting
@u:DISTIL,p:DISTIL input,n:DISTIL atom selection
構造weight用option:
    -p,  --prob FILE      A/B共通probability file
    -pA, --probA FILE     ensemble A用probability file
    -pB, --probB FILE     ensemble B用probability file

ALSDの再重み付け後など、構造ごとの統計weightが異なる場合に指定します。通常MDではprobability fileを省略でき、その場合は全構造へ等weightが与えられます。
>DISTIL atom selection
@u:DISTIL,p:DISTIL weighting,n:DISTIL feature generation
原子選択option:
    -a,  --atom-spec EXPR     A/B共通selection（default: !H*,h*）
    -aA, --atom-specA EXPR    A用selection（-aより優先）
    -aB, --atom-specB EXPR    B用selection（-aより優先）

等価原子の扱い:
    -ea, --equiv-atoms {aggregate,report}
        aggregate（default）は化学的等価原子の置換距離を同一特徴の分布へ統合します。reportは統合せず診断情報を出力します。
    -em, --equiv-map CSV
        非標準残基やligandの等価原子定義を追加します。

selection書式は"atom specifier"を参照し、shellで解釈されないよう引用符で囲んでください。
>DISTIL feature generation
@u:DISTIL,p:DISTIL atom selection,n:DISTIL standard mode
DISTILは二種類の相補的な距離特徴を使用します。
    1. 局所相互作用変化を表すnear-contact原子pair距離
    2. 中・長距離再配置を表すnon-contact残基pair距離

主要option:
    -cd, --contact-distance DISTANCE
        near-contact cutoff（Å、default: 6.0）
    -t, --tpl FILE
        A/B共通j_presto topology。指定すると結合関係にある原子pairをnear-contact候補から除外します。
    -tA / -tB
        A/B別topology
    -teu, --tpl-exclude-up-to N
        N bond以内の関係を除外（default: 2、すなわち1-2・1-3 pair）

化学結合した局所pairが特徴へ混入する可能性がある場合、topologyの指定を推奨します。
>DISTIL standard mode
@u:DISTIL,p:DISTIL feature generation,n:DISTIL CED mode
standard modeは、二つのensembleを明確に識別できる距離特徴を選択します。

例:
    j_presto DISTIL -A A.list -B B.list -r reference.pdb -sm standard

主要optionとdefault:
    -sm,  --selection-mode standard
    -s1c, --tv-threshold 0.35      AUC計算前のTotal Variation prefilter
    -at,  --auc-threshold 0.80     hold-out単一特徴AUCの最低値
    -ak,  --auc-cv-folds 5         hold-out AUC・寄与推定のfold数
    -bm,  --bins-max 128           histogram最大bin数

選択特徴はsingle-pair scoreへ変換され、L1正則化logistic regressionにより冗長性を抑えながら相対寄与を推定します。AUCは入力された二ensembleの分離度を内部評価するためのものであり、未知構造の予測を主目的としません。
>DISTIL CED mode
@u:DISTIL,p:DISTIL standard mode,n:DISTIL bundling and regions
Condition-Excess Difference（CED）modeは、個々の構造を高精度に分類できない弱い条件依存差を調べるための補助modeです。各条件に複数の独立runが必要で、観測A/B差を、条件内run間変動およびcondition labelを無視したpooled-label nullと比較します。

例:
    j_presto DISTIL -A A.list -B B.list -r reference.pdb -sm ced

主要default:
    -cws,  --ced-within-splits 100
    -cns,  --ced-null-splits 999
    -cmt,  --ced-min-tv 0.02
    -crt,  --ced-r-threshold 1.5
    -czt,  --ced-z-threshold 2.0
    -cnrt, --ced-null-r-threshold 1.2
    -cnzt, --ced-null-z-threshold 1.0
    -cnqt, --ced-null-q-threshold 0.05

ensemble listでは独立simulation runを別run groupとして記述してください。一つのtrajectoryを連続segmentへ分割しただけのdataを、独立runとして扱わないでください。
>DISTIL bundling and regions
@u:DISTIL,p:DISTIL CED mode,n:DISTIL output
特徴選択後、DISTILは選択距離をnodeとするfeature graphを作り、閾値以上の正相関edgeを保持してcommunity detectionによりbundleへまとめます。

主要option:
    -ct, --corr-tau VALUE
        最小正相関（default: 0.95）
    -cm, --community-method {auto,leiden,louvain}
        community detection法（default: auto）
    -mmi, --maxcut-max-iter N
        weighted Max-Cutの最大local improvement回数（default: 1000）
    -mr, --maxcut-restarts N
        bundleごとのMax-Cut restart数（default: 3）

各bundleを構造graphへ写像し、weighted Max-Cutで二領域へ分割します。二領域を横切る特徴のうちscore最大の距離を代表距離としてranking・可視化します。

>DISTIL output
@u:DISTIL,p:DISTIL bundling and regions,n:DISTIL output main results
DISTILは、-o/--outdirで指定したdirectoryの下に全解析artifactを出力します。出力には、最終結果表、特徴・bundleの詳細表、可視化file、実行条件metadata、および再開用cacheが含まれます。

最初に確認する順序:
    1. analysis_summary.tsv
    2. ranked_pairs_pretty.txt
    3. pair_contrib_ranked_pretty.txt
    4. 上位構造領域pairに対応するplots/およびpdb/

最終選択を通過する特徴がない場合、DISTILはheaderのみの結果表を作り、人間向けtext fileには理由を記録します。これはprogramの失敗ではなく、差が検出されなかったという有効なnegative resultです。analysis_summary.tsvとrun_provenance.jsonを確認し、run statusが完了していることを確認してください。

主要出力option:
    -np, --topN-pairs N
        ranked出力へ書く構造領域pairの最大数（default: 200）
    -pf, --plot-format {png,pdf}
        距離分布plot形式（default: png）
    -pd, --plot-dpi N
        PNG出力のDPI（default: 150）
    --stage5-output-top-regions N
        上位N構造領域pairについて、個別の距離分布、PDB、PyMOL出力を作成（default: 20）。0で個別可視化を無効化します。
    --stage5-write-all-individual-visuals
        report対象の全構造領域pairについて個別可視化を作成します。大量のfileが生成され、実行時間とdisk使用量が大きくなる場合があります。

>DISTIL output main results
@u:DISTIL,p:DISTIL output,n:DISTIL output feature and bundle tables
次のfileがDISTILの最終結果を要約します。

    analysis_summary.tsv
        直接確認しやすい二列形式の要約です。frame数、run数、候補・選択特徴数、bundle数、構造領域pair数、実際に使用したcommunity detection法、および最上位構造領域pairを記録します。

    analysis_summary.json
        同じ要約のmachine-readable版です。top_ranked_region_pairにはranked_pairs.csvの第1行全体が保存されます。

    ranked_pairs_pretty.txt
        人が読むための主要結果です。最終ranking順に、使用されたranking score、bundle ID、代表交差特徴（argmax_pair_id）、主要なsupporting feature、およびRegion A/Region Bを構成するnodeを表示します。

    ranked_pairs.csv
        --topN-pairsで指定した件数までの、machine-readableな構造領域pair rankingです。rankが表示順、bundle_idがbundle・特徴表との対応を表します。argmax_pair_idは、そのrankの距離分布plotに使用される代表距離特徴です。

    bundle_regions_pretty.txt
        各bundleの領域分割を人が読める形で示します。rank、Max-Cut結果、代表特徴、主要な交差特徴、および両領域の構造要素を含みます。

    bundle_regions.csv
        bundleから二領域への対応を保存したmachine-readable表です。行はbundle_id順で、rank列、領域node、交差特徴の統計量、ranking構成値、代表・supporting feature IDを含みます。

    ranking_mode.json
        Stage5で実際に使用したranking mode、特徴weight式、主要score列、辞書式ranking policy、およびtie-break policyを記録します。異なるselection modeの結果を比較するときに参照してください。

    global_ensemble_difference.txt
        ensemble全体のmultivariate分離AUCです。standard modeのcontribution modelで意味を持ち、そのmodelを使用しないmodeではNAとなる場合があります。

    contribution_status.json
        multivariate contribution modelの状態と診断情報です。fitted/hold-out AUC、および非zero model特徴数等を記録します。

>DISTIL output feature and bundle tables
@u:DISTIL,p:DISTIL output main results,n:DISTIL output visualization files
次のfileは、候補距離特徴がbundleおよびranked構造領域pairへ変換される過程を記録します。容量が大きくなる場合があります。表同士はfid（feature ID）とbundle_idで対応付けます。

    top_pairs_pool.csv
        全候補距離特徴の定義表です。near/longの種別、原子または残基endpoint、atom group、等価原子groupを記録します。feature列が下流表で使用されるfidです。

    pair_scores.csv
        全候補特徴のStage1 metric表です。TV、計算対象となった場合のhold-out AUC、各selection flag、分布統計量、transport量、および選択modeに応じたsignificance/CED統計量を含みます。通常、最も大きなtext出力の一つです。

    feature_metrics/all_feature_metrics.csv
        feature_metrics directoryに保存されるStage1の完全監査表です。最初の結果解釈よりも、詳細filteringや手法検証に使用します。

    pair_contrib.csv
        最終的に下流解析へ渡された特徴の表です。Stage1 metric、利用可能な場合のmultivariate係数・寄与、active Stage5 score、およびbundle_idを統合します。standard modeではcontribution_multi、sig modeではsig_strength、CED modeではcondition_effect_scoreがactive scoreです。

    pair_contrib_ranked.csv
    pair_contrib_ranked_pretty.txt
        選択特徴をactive Stage5 score順に並べたmachine-readable版と人間向け版です。最終結果を強く支持する個別距離を確認するときに使用します。

    feature_corr_edges.csv
        --corr-tau以上の正相関を持つfeature graphのedge表です。各行はf_idとg_id、および相関係数を記録します。

    bundles.csv
        feature graphから得られたbundle membershipです。member_fidsはsemicolon区切りのfeature ID、bundle_sizeはmember数です。

    residue_contrib.csv
        特徴寄与を残基単位で集約した表です。near/long成分とsupporting feature数を別々に記録します。

    region_contrib.csv
        bundle・regionごとの寄与、pair数、およびsingle-feature AUCの集約表です。これは診断表であり、最終的な領域順はこのfile単独ではなくranked_pairs.csvで定義されます。

>DISTIL output visualization files
@u:DISTIL,p:DISTIL output feature and bundle tables,n:DISTIL output metadata and optional analyses
可視化fileは主にplots/とpdb/へ出力されます。NNNNは0001のようにzero paddingされた1始まりの構造領域pair rankです。

    plots/pair_rankNNNN_dist.png
    plots/pair_rankNNNN_dist.pdf
        その構造領域pairの代表交差特徴（argmax_pair_id）について、ensemble A/Bのweight付き距離分布を示します。titleには特徴identityと、関連するTV、AUC、contribution、sig、またはCED統計量が表示されます。sig modeではrun-level error bandを表示します。standard modeでは、複数run groupがあり-pre/--plot-run-errorbarsを指定した場合に表示します。

    pdb/pair_rankNNNN_regions.pdb
        一つのranked構造領域pairを参照構造へ投影したPDBです。選択原子のB-factor fieldには、bundle member特徴からmax集約し、そのfile内で0–1へ正規化したactive Stage5 atom scoreが保存されます。利用可能な場合、occupancy fieldには対応するAUC値が保存されます。PDB単体にはRegion A/Bの色は保存されません。

    pdb/pair_rankNNNN_view.pml
        上記PDBと組み合わせて使用するPyMOL scriptです。Region Aを赤、Region Bを青で表示し、連続score mapを適用します。

    pdb/all_ranked_bundles_regions.pdb
    pdb/all_ranked_bundles_view.pml
        ranked出力に含まれる全構造領域pairを統合したscore projectionです。意図したPyMOL表示を再現するにはPML fileを使用してください。

    pdb/*_metric_*.pdb
    pdb/metric_pdbs.json
        個別metricの原子projectionです。Stage1ではTV、AUC、significance、CED map、Stage5ではranked bundle特徴に基づくcontributionおよびmode固有metricを出力します。各PDBのB-factor fieldに保存されたmetric、使用feature集合、原子への集約法はmetric_pdbs.jsonを正式な説明として参照してください。

    ensemble_direction_map.tsv
    ensemble_direction_map.bild
    ensemble_direction_map.cmd
        weight付き特徴分布差から得られるA→B方向の要約です。TSVは原子ごとのvector、BILDは表示arrow、command fileはreference_A_selected.pdbとともにUCSF Chimeraで開くための命令を保存します。このarrowはensemble差の要約であり、物理的な原子trajectoryを表すものではありません。

>DISTIL output metadata and optional analyses
@u:DISTIL,p:DISTIL output visualization files,n:DISTIL cache and restart
次のfileは、再現性、入力検査、再開、および任意解析を支えるものです。通常、構造差を最初に解釈するときの主要fileではありません。

実行条件・入力記録:
    args_requested.json
        正規化とdefault解決前に指定されたargument
    args_used.json
        解析で実際に使用された有効argument
    run_provenance.json
        DISTIL version・SHA256、command、入力checksum、package version、random state、platform情報、cache version、およびrun status
    features_meta.json
        feature生成metadata、およびfeature artifactのpath・checksum
    reference_A_selected.pdb / reference_B_selected.pdb
        各ensembleで実際に選択された参照原子
    atom_mapping_A_to_B.csv
        二つの参照構造間で検証された選択原子対応
    reference_geometry_A.csv / reference_geometry_B.csv
        不審な入力geometryを検出するための参照構造診断
    equiv_atom_groups.csv / equiv_atom_rejected_groups.csv
        採用・棄却された等価原子group。対応するJSON fileは診断schemaとCSV locationを記録します。

binary・integrity artifact:
    weights_A.npy / weights_B.npy
        解析で使用した正規化frame weight
    pair_index.npy / sel_fids.npy
        内部feature indexと最終選択feature配列
    .*.sha256.json および *.ok
        cache検証用integrity marker。これらを編集しないでください。

任意出力directory:
    representatives/
        -xr/--extract-representativesで作成されます。A-like/B-like代表構造PDB、representatives_summary.csv、representative_features_used.csv、representatives_info.txtを含みます。
    stability/
        -sr/--stability-runsを0より大きくした場合に作成されます。pair_stability.csv、bundle_stability.csv、region_stability.csv、run_stability.csv、summary.txtを含みます。
    dist_plots/
        -dpp/--dist-plot-pairを用いる直接距離plot modeで作成されます。

DISTILの進行状況とwarningはterminalへ出力され、固定log filenameは必要としません。実行logを保存する場合は、shellまたはjob scriptで標準出力・標準errorをredirectしてください。

>DISTIL cache and restart
@u:DISTIL,p:DISTIL output metadata and optional analyses,n:DISTIL examples
DISTILは、再開可能な中間結果をdistil_cache/と出力directory直下の一部binary artifactへ保存します。これらは実装用dataであり、最終的な科学結果ではありません。個別cache fileを手作業で編集しないでください。

distil_cache/には、Stage1 scoring/checkpoint、Stage2 contribution model、Stage3 correlation、Stage4 bundle metadata、Stage5 region・ranking metadata、direction map metadata、および任意のStage6 stability replica等が保存されます。.done.jsonとmetadata fileは、完了stageを再利用できるか判断するためのsignatureを記録します。

option:
    -f, --force
        互換性のあるfeature poolを保持し、feature生成後のpipeline stageを再計算
    -frf, --force-recompute-features
        pool・feature cacheを無視して再生成し、feature cacheからの自動resumeも無効化
    -na, --no-accelerate
        disk cacheとJIT accelerationを無効化
    -sc, --self-check
        軽量内部smoke testを実行し、解析artifactを作らず終了

中断した解析を再開するには、出力directory全体を保持してください。解釈に必要な最終text/CSVと可視化fileだけを別archiveへコピーすることはできますが、その縮小archiveから計算を再開することはできません。分子systemまたは原子対応を変更した場合は新しい出力directoryを使用してください。trajectory、参照構造、topology、atom selection、feature生成設定を変更した場合は-frfを使用してください。

"j_presto distrib"は、1～3次元の数値dataをweightおよびsub-group情報とともに解析し、分布、平均・標準誤差、または自由energy landscapeを作成します。TTPで得た複数独立runの結果を統合し、各runをsub-groupとしてrun間平均と標準誤差を計算できます。

    distrib -o      出力prefix
    distrib -f      DIST/NORM/LOG/FEL
    distrib -a      x, y, zに使うcolumn
    distrib -w      weight column
    distrib -s      sub-group情報

>distrib -i
@u:distrib,n:distrib -o
使用法: j_presto distrib -i INPUT [INPUT ...]

解析する空白またはtab区切りの数値text fileを指定します。各行が一data pointです。複数fileを指定できます。解析columnは-a、weight columnは-wで指定します。file間で行数は異なっても構いませんが、使用するcolumn構造は整合させてください。必須optionです。
>distrib -o
@u:distrib,p:distrib -i,n:distrib -f
使用法: j_presto distrib -o OUTPUT

*.avg、*.dist等の全出力fileに共通するprefixを指定します。

@u:distrib,p:distrib -o,n:distrib -a
使用法: j_presto distrib -f {DIST,NORM,LOG,FEL}

出力する分布形式を指定します。
    DIST  raw distribution（default）
    NORM  正規化分布
    LOG   分布のlog変換
    FEL   自由energy landscape

@u:distrib,p:distrib -o,n:distrib -w
使用法: j_presto distrib -a COL_NUM1 [COL_NUM2 [COL_NUM3]]

入力fileのどのcolumnを変数として使うか指定します。1 columnならx軸の1D分布、2 columnならx-y平面の2D分布、3 columnならx-y binごとにz値の平均とsub-group間標準誤差を計算します。

@u:distrib,p:distrib -a,n:distrib -s
使用法: j_presto distrib -w COL_NUM

@u:distrib,p:distrib -w,n:distrib -r
使用法: j_presto distrib -s {TTPNCNF_FILE,COLUMN_NUMBER,NFILE}

@u:distrib,p:distrib -s,n:distrib -t

使用法: j_presto distrib -xnorm

>conmut
@u:j_presto,p:MSPER,n:struct_formula
"j_presto conmut"はblastpでquery蛋白質のhomolog配列を収集し、MAFFTまたはClustalWでmultiple sequence alignmentを行い、consensus配列に基づく置換候補を提案します。query配列自身はalignmentへ含めますがconsensus投票から除外されます。保存性の高い残基への置換候補は、蛋白質安定性、特に耐熱性改善の候補として利用できますが、実際の効果は別途検証してください。

使用法: j_presto conmut QUERY.fasta [options]

option:
    conmut -e   web BLAST用email
    conmut -l   local BLASTを使用
    conmut -d   local database path（default: nr）
    conmut -b   E-value threshold（default: 1e-5）
    conmut -m   最大target配列数（default: 1000）
    conmut -i   最小identity（default: 0.9）
    conmut -c   最小coverage（default: 0.9）
    conmut -H   homolog FASTAを直接入力しBLASTを省略
    conmut -a   aligner（mafft/clustalw、default: mafft）
    conmut -s   出力残基番号の開始値（default: 1）
    conmut -o   出力prefix（default: result）

出力には*_all.fasta、*_flt.fasta、*_res.fasta、*_aln.fasta、*_consensus.fasta、*_aln_view.txt、*_suggested_mutations.txtが含まれます。

@u:conmut,n:conmut -l

>atom specifier
複数のj_presto programで原子選択に使用する共通書式です。一つ以上のselection blockをlogical operatorで連結します。式中に空白を入れず、!、&、|、<、parenthesesを含む場合はshellで引用符に入れてください。

1. atom ID・残基・chain・原子名
    14              atom ID 14
    1<20            atom ID 1～20
    10<30,40<50     10～30および40～50
    CA              原子名CA
    N,CA,C,O        protein backbone
    C*              Cで始まる原子名
    !H*,h*          H/hで始まらない原子

* wildcardは名前末尾だけで使用できます。block先頭の!は否定です。

残基・原子:
    1<20:CA         残基1～20のCA
    LYS,ARG:*       LYS/ARGの全原子
    WAT:O           水oxygen
    !ALA:*          ALA以外の全原子

chain・残基・原子:
    1:*:*           第1 chainの全原子
    A,B:ARG:CA      chain A/BのARG CA

2. 座標範囲
    [-5.0<5.0:2<:<-3]
        x=-5～5、y>=2、z<=-3
    [-2<-1,1<2::]
        x=-2～-1または1～2

3. block連結
&はAND、|はORです。
    !H*,h*&[:5<:]
        non-hydrogenかつy>=5
    1<5:CA|11<20:N
        残基1～5のCA、または11～20のN

式は左から評価されます。意図する優先順位を明確にする場合はparenthesesを使用してください。

        -b 1001 -e END -s 10 -as '!H*,h*'

大きな出力前には-c/--check_onlyで条件を検査してください。変換後、traj_convが作成した付随PDBを、原子順序一致が必要なj_presto解析の参照PDBとして使用します。

>tutorial DISTIL

>tutorial PCA
@u:tutorial

>tutorial PCA 1
@u:tutorial PCA,n:tutorial PCA 2
Ens_Anaで*.PCAcodを作成します。

Cartesian座標PCAはnative付近の揺らぎ解析に適し、PCA_method=cordとatom_spec_PCAを設定します。並進・回転差を除くため通常はRMSD fittingも指定します。

残基間距離等のinternal coordinate PCAは大きな構造変化、folding、McMD/ALSD ensembleに適します。PCA_method、atom_spec_PCA、neighbor_residue_PCA、必要ならtolerance_PCAを設定します。

設定後"j_presto Ens_Ana"を実行してください。詳細は"PCA_method"と"Ens_Ana.inp"を参照します。
>tutorial PCA 2
@u:tutorial PCA,p:tutorial PCA 1,n:tutorial PCA 3
*.PCAcodからPC軸を計算します。
    j_presto PCAaxis -i input.PCAcod -o result
次に、各構造を*.axisへ射影します。
    j_presto PCAproj -i input.PCAcod -a result.axis -o result
詳細は"PCAaxis"と"PCAproj"を参照してください。
>tutorial PCA 3
@u:tutorial PCA,p:tutorial PCA 2
PCAprojが出力した*.projをdistribへ入力し、PC空間上の分布または自由energy landscapeを作成します。*.projのcolumn 1はweight、column 2以降がPC座標です。

1D/2Dで使用するcolumnを-a、weightを-w、FELなら-f FELで指定します。distribは1Dで*.dist、2Dで*.distpを出力します。gnuplot templateは"j_presto get_tmpl gnu.plot"または"gnu.splot"で取得できます。
>tutorial MSPER
@u:tutorial
MSPER workflowは次の4段階です。
    1. enzyme-substrate複合体ensembleをMD等で作成
    2. Ens_Anaとpick_confでdesirable/undesirable ensembleを抽出
    3. 各ensembleで酵素原子と基質のcontact率をEns_Anaで計算
    4. 二つの*_con.pdbをMSPERへ入力し変異候補をranking

1. regioselectivity改善では、目的反応siteが活性中心へ近いposeをdesirable、他siteが近いposeをundesirableとします。substrate selectivity改善では各substrateのensembleを用意します。

2. Ens_Anaのmeasurementsで活性中心－反応site距離を*.distanへ出力し、pick_confでthresholdを満たす構造を*.listとして抽出します。

3. *.listをEns_Anaのinput_binary_listへ指定し、atom_spec_contactでenzymeをtarget、substrateをprobeとしてcontact率を*_con.pdbへ出力します。desirable/undesirableの双方で行います。

4. 例:
    j_presto MSPER -d desirable_con.pdb -u undesirable_con.pdb -o result
*.scrと*.listが出力されます。sampling convergence確認のため、独立初期構造・simulation setごとにMSPERを行い、ranking一致を確認することを推奨します。複数結果は次で統合できます。
    j_presto MSPER -s 1.scr 2.scr

>FAQ prep disulfide and LINK records
@u:FAQ prep,n:FAQ prep DNA trimming
質問:
    disulfide bondやその他の共有結合linkを導入するにはどうすればよいですか。

回答:
    disulfide bondは入力PDBのSSBOND record、その他の共有結合はLINK recordで記述します。prepは適切なparameterが存在する場合、これらを読みtopology connectionへ反映します。残基名・原子名がtopology databaseと一致していることを確認し、column形式はPDB format specificationを参照してください。
>FAQ prep DNA trimming
@u:FAQ prep,p:FAQ prep disulfide and LINK records,n:FAQ prep terminal caps
質問:
    system trimmingでDNA二重鎖の片方だけが削除されます。pairを残すにはどうすればよいですか。

回答:
    "j_presto prep -pair"で、一緒に保持すべきDNA chainまたはsegment pairを指定します。書式は"prep -pair"を参照してください。
>FAQ prep terminal caps
@u:FAQ prep,p:FAQ prep DNA trimming
質問:
    peptide chain末端chargeを中和するにはどうすればよいですか。

回答:
    N末端へacetyl capを付けるには"j_presto prep -ACE"、C末端へN-methylamide capを付けるには"j_presto prep -NME"を使用します。残基selectionの書式は各項目を参照してください。

>FAQ md_run memory
@u:FAQ md_run,n:FAQ md_run parallelization
質問:
    md_runがmemory allocation、stack、OpenMP関連errorで停止します。

回答:
    まずOMP_NUM_THREADSを減らし、要求memoryがcompute nodeの上限内か確認してください。bash環境では例として次のように設定できます。
        ulimit -s 16384
        export OMP_STACKSIZE=16M
        export OMP_NUM_THREADS=8
        j_presto md_run md.inp > md.log

thread数を増やすとthreadごとのmemoryも増え、常に高速化するとは限りません。ulimit -sは通常KB、OMP_STACKSIZEは16M等で指定します。必要値はcompiler、OS、scheduler、system sizeに依存します。両値を機械的に同じ数値へせず、利用環境の規則に従ってください。
>FAQ md_run parallelization
@u:FAQ md_run,p:FAQ md_run memory
質問:
    どのようなparallel実行に対応していますか。

回答:
    一つのmd_run processはOpenMP shared-memory parallelizationを使用します。単一trajectoryをMPIでdomain decompositionするengineではなく、GPUも直接使用しません。一つのMPI allocation内で複数独立OpenMP trajectoryを実行する場合はj_presto_mpiまたはj_presto_masterを使用します。
